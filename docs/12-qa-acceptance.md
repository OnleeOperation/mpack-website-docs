# 12 — QA and Acceptance Checklist

# Content

- [ ] M-Pack name is consistent.
- [ ] No fabricated impact statistics.
- [ ] No unverified partner relationships shown as confirmed.
- [ ] No class-model revenue target shown as actual performance.
- [ ] Mission language is verified or flagged.
- [ ] Product inventory is real or clearly demo data.
- [ ] Donor tiers/perks are verified or clearly demo data.

# Safeguarding

- [ ] No child profile pages.
- [ ] No child full names on products.
- [ ] No sensitive ACE/case history.
- [ ] No unapproved faces.
- [ ] No internal behavior data.
- [ ] Public stories are privacy-safe.
- [ ] Internal source docs are not downloadable from the public site.

# UX

- [ ] Navigation works.
- [ ] Primary CTA is obvious.
- [ ] Mobile menu works.
- [ ] Shop is understandable.
- [ ] Donors' Club is understandable.
- [ ] Corporate path is easy to find.
- [ ] Newsletter has success/error states.
- [ ] Empty-cart state exists if cart is implemented.
- [ ] Sold-out state exists.
- [ ] No dead buttons.

# Accessibility

- [ ] Keyboard navigation works.
- [ ] Visible focus states.
- [ ] Semantic heading order.
- [ ] Form labels exist.
- [ ] Errors are descriptive.
- [ ] Contrast is acceptable.
- [ ] Reduced motion is respected.
- [ ] Images have correct alt text.

# Performance

- [ ] No huge unoptimized images.
- [ ] No unnecessary client-side libraries.
- [ ] Fonts load efficiently.
- [ ] Homepage performs well on mobile.

# Technical

- [ ] Lint passes.
- [ ] Typecheck passes.
- [ ] Build passes.
- [ ] Environment variables are documented.
- [ ] Secrets are not committed.
- [ ] No console errors on core flows.

# Demo readiness

- [ ] Homepage can be shown in under 60 seconds.
- [ ] Craft flow works without broken checkout.
- [ ] Newsletter demo produces clean success state.
- [ ] Donors' Club has a clear CTA.
- [ ] Partner inquiry path works.
